## 一、先抓住 CLIP 的核心

CLIP 的全称是 **Contrastive Language-Image Pre-training，对比语言-图像预训练**。

可以把它理解为两个阶段：

1. **预训练**：从大量图文配对中，学习“什么图像与什么文字相对应”。
2. **零样本推理**：把候选类别写成文字，与输入图像比较相似度，选出最匹配的类别。

因此，CLIP 的关键不只是“图像特征提得好”，还在于：

**它把图像表示与自然语言连接起来，使分类器可以由文字描述动态构造，而不是只能输出训练时固定的类别。**

例如，一个只训练过 ImageNet 1,000 类分类头的模型，不能直接增加一个“红包”输出项；CLIP 则可以把 `red envelope` 加入候选文本，再进行相似度比较。它不需要为这一步重新训练分类头，但能否识别正确，仍取决于模型能力、图像内容和候选描述。

## 二、研究动机：为什么用自然语言监督

### 2.1 固定类别监督的限制

传统图像分类通常先定义一个类别集合，再收集对应图片和标签，训练一个固定维度的分类头。

这种流程很适合标准任务，却带来两个限制：

- **扩展数据需要额外标注**：新增视觉概念时，通常还要收集和标注样本。
- **输出空间固定**：模型最终只能在预先定义的类别中选择，不能仅凭一个新类名增加新的输出能力。

CLIP 想回答的是：能否直接利用互联网上已有的图像及其配文，训练一个能够迁移到不同任务和数据集的视觉模型？

### 2.2 自然语言提供了什么

与类别编号相比，一段文字可能同时表达对象、属性、动作和场景。

**整理理解**：类别标签往往只说“这是什么”，而配文还可能说“它在做什么、是什么颜色、处于什么环境”。CLIP 并不保证把这些信息都学会，但这种监督形式不再受某一个固定标签表约束。

论文 §2.1 强调了两点：

1. **更容易扩大规模**：不要求每个样本都采用人工定义的单一类别标签格式。
2. **表示与语言相连**：不仅学习视觉特征，还获得了通过文字指定下游分类任务的接口。

### 2.3 到底算有监督，还是自监督

视频中交替使用了“无监督”“自监督”等表述。论文专门指出，相关工作确实使用过不同命名。

更稳妥的说法是：**CLIP 使用自然语言监督。**

它不需要为某个固定分类任务逐张添加类别标签，但图文配对本身就是监督信号。不能把“不需要额外人工类别标注”理解成“训练中没有任何监督”。

**对应视频**：00:16:02-00:36:47；论文 §1、§2.1。

## 三、数据：为什么需要 4 亿图文对

### 3.1 现有数据的问题

视频比较了几类当时常见的图文数据：

| 数据来源                  | 主要问题                         |
| --------------------- | ---------------------------- |
| MS-COCO、Visual Genome | 标注质量较高，但训练图像规模约为十万量级         |
| YFCC100M              | 规模较大，但配文质量不一致，部分只是文件名或相机参数   |
| 过滤后的 YFCC100M         | 保留英文自然语言标题或描述后，约剩 1,500 万张图像 |

如果配文只是 `20160716_113957.JPG`，它对学习视觉语义的帮助就很有限。可扩展的图文学习既需要数量，也需要配对文字中有可用信息。

### 3.2 WIT 数据集

论文构建了 **WIT，WebImageText**，包含从互联网收集的 **4 亿对图像与文本**。

**论文补充核查，§2.2**：

- 收集过程使用约 **50 万个查询词或短语**，寻找文本中包含相应查询的图文对。
- 每个查询最多纳入 **20,000 对**，以近似平衡概念覆盖。
- 这不是一个由 50 万个互斥类别组成的人工分类数据集。

需要区分“按查询收集和筛选数据”与“所有配文都准确、充分清洗且无社会偏见”。视频开头推测数据质量很高，后面又讨论了未充分过滤的互联网数据带来的偏见。论文能支持前者的收集策略，**不能支持整套数据已经无噪声、无偏见的强结论**。

### 3.3 规模重要，但不是唯一解释

视频强调了数据、模型和计算规模共同扩大的作用。

这不等于“只要数据够多就一定成功”。CLIP 还需要一个能够在这种规模下有效训练的目标函数，下一节的对比学习正是关键。

**对应视频**：00:27:26-00:31:19、00:36:49-00:39:15；论文 §2.2。

## 四、方法：让正确的图文配对更接近

### 4.1 双编码器架构

![CLIP 官方架构图](CLIP%20论文精读.assets/CLIP.png)

*图源：OpenAI/CLIP 官方仓库的 `CLIP.png`。图中展示了图文对比预训练、用文本构造分类器，以及零样本预测三个环节。[^code]*

CLIP 包含两个编码器：

- **图像编码器**：把图像转换为向量，论文采用改进的 ResNet 或 Vision Transformer。
- **文本编码器**：把文本转换为向量，正式模型采用 Transformer。

两侧的表示经过各自的线性投影，映射到同一个维度的嵌入空间，再进行 L2 归一化。

设一批输入为：

$$
\{(x_i,y_i)\}_{i=1}^{N},
$$

其中 $x_i$ 是图像，$y_i$ 是与它配对的文本。定义：

$$
u_i=\frac{f_\theta(x_i)W_I}
{\|f_\theta(x_i)W_I\|_2},
\qquad
v_i=\frac{g_\phi(y_i)W_T}
{\|g_\phi(y_i)W_T\|_2}.
$$

这里 $u_i,v_i$ 都是单位长度向量，因此点积 $u_i^\top v_j$ 就是余弦相似度。

**整理理解**：“共享嵌入空间”指两种模态的输出可以直接比较，不是说两个编码器共享全部网络参数，也不是把图像和文字先拼接起来送进同一个网络。

### 4.2 正负样本如何定义

给定一个包含 $N$ 对图文的 batch，计算所有图像与所有文本的相似度，得到 $N\times N$ 矩阵：

$$
S_{ij}=\alpha u_i^\top v_j,
\qquad
\alpha=\exp(t)=1/\tau.
$$

- 对角线 $(i,i)$：真实图文配对，共 $N$ 个正配对。
- 非对角线 $(i,j),i\ne j$：按训练目标视作不匹配，共 $N^2-N$ 个负配对。

例如，一个三对样本的 batch：

|  | 文本 1 | 文本 2 | 文本 3 |
| --- | --- | --- | --- |
| 图像 1 | 正配对 | 负配对 | 负配对 |
| 图像 2 | 负配对 | 正配对 | 负配对 |
| 图像 3 | 负配对 | 负配对 | 正配对 |

**整理理解**：非对角线是训练中的负配对定义，不保证其语义一定互斥。如果同一批里恰好有两张同类对象及相近描述，可能出现语义上也匹配的“假负例”。

### 4.3 为什么要算两个方向的损失

CLIP 同时训练两个任务：

1. 给定图像，在 batch 的所有文本中找到对应文本。
2. 给定文本，在 batch 的所有图像中找到对应图像。

图像到文本方向：

$$
\mathcal L_{I\rightarrow T}
=-\frac{1}{N}\sum_{i=1}^{N}
\log
\frac{\exp(S_{ii})}
{\sum_{j=1}^{N}\exp(S_{ij})}.
$$

文本到图像方向：

$$
\mathcal L_{T\rightarrow I}
=-\frac{1}{N}\sum_{i=1}^{N}
\log
\frac{\exp(S_{ii})}
{\sum_{j=1}^{N}\exp(S_{ji})}.
$$

最终损失是：

$$
\mathcal L
=\frac{\mathcal L_{I\rightarrow T}
+\mathcal L_{T\rightarrow I}}{2}.
$$

**核心直觉**：正确配对不仅要相似，还要在当前候选集合中比其他配对更相似。

### 4.4 温度参数有什么用

$\tau$ 控制 softmax 分布的尖锐程度；等价地，$\alpha=1/\tau$ 控制相似度 logits 的缩放。

- $\alpha$ 越大，相似度的细小差异被放大，分布通常越尖锐。
- $\alpha$ 越小，分布通常越平缓。

CLIP 学习的是一个对数参数化的缩放标量，不是把温度固定下来后反复手工搜索。论文 §2.5 说明，温度初始化对应 $\tau=0.07$，并限制 logits 的缩放不超过 100。

**实现边界**：论文描述的训练期裁剪，不能直接等同于公开 `model.py` 的推理 `forward` 中有裁剪；公开实现这里使用的是 `self.logit_scale.exp()`。[^paper][^code]

### 4.5 用代码看清整个目标

下面是依据论文图 3 重写的**单设备教学版核心损失**，不是完整预训练脚本：

```python
import torch
import torch.nn.functional as F


def clip_contrastive_loss(image_features, text_features, logit_scale):
    # Inputs are projected image/text embeddings of shape [N, D].
    image_features = F.normalize(image_features, dim=-1)
    text_features = F.normalize(text_features, dim=-1)

    logits = logit_scale.exp() * image_features @ text_features.T
    labels = torch.arange(logits.shape[0], device=logits.device)

    loss_i = F.cross_entropy(logits, labels)
    loss_t = F.cross_entropy(logits.T, labels)
    return (loss_i + loss_t) / 2
```

这里有三个容易混淆的点：

- `labels` 是配对位置，不是图像所属的语义类别编号。
- `torch.arange(N)` 得到的是 `0, 1, ..., N-1`。视频口述为“1 到 n”，不能照搬成 Python 下标。
- 完整大规模训练还涉及跨设备特征、梯度传播、数值稳定性和温度约束；这段代码不覆盖这些工程细节。

## 五、为什么不用生成配文作为主要目标

视频强调：对一张图像，合理的文字描述可能有很多种。有人关注物体，有人关注颜色，也有人关注动作。

如果要求模型逐词预测某一条具体配文，模型就要处理表达形式、词序以及与视觉表征学习不完全一致的语言细节。

对比学习把任务改成：

**不要求还原这段话的全部词语，只要求从候选中判断哪段文字与图像配对。**

论文图 2 比较了：

| 路线                   | 在该实验中的观察              |
| -------------------- | --------------------- |
| Transformer 语言模型预测配文 | 零样本 ImageNet 学习效率较低   |
| 预测文本的词袋表示            | 比上述配文生成基线约快 3 倍       |
| 对比式图文匹配              | 在词袋预测基线上，再获得约 4 倍效率提升 |

**口径提醒**：这里的“快”是按论文图 2 的零样本 ImageNet 学习效率比较，不是说任意对比模型的训练吞吐或推理延迟都能提高相同倍数。

这也不证明生成目标没有价值。论文局限性部分反而提出：可以尝试联合对比与生成目标，结合效率与输出灵活性。

**对应视频**：00:39:17-00:43:27、01:25:04-01:26:02；论文 §2.3、§6。

## 六、模型和训练：简单目标背后的工程规模

### 6.1 八个视觉模型

| 系列     | 模型                                |
| ------ | --------------------------------- |
| ResNet | RN50、RN101、RN50x4、RN50x16、RN50x64 |
| ViT    | ViT-B/32、ViT-B/16、ViT-L/14        |

`RN50x4/x16/x64` 指近似计算量相对 RN50 的倍数，不是只把某一层宽度直接乘相应倍数。论文同时调整宽度、深度和输入分辨率。

`ViT-B/32` 中的 `/32` 则表示 patch 大小，不是网络层数。

### 6.2 主要训练设置

| 项目            | 论文设置                   |
| ------------- | ---------------------- |
| 初始化           | 图像与文本编码器均从零训练          |
| 训练轮数          | 32 epochs              |
| 全局 batch size | 32,768                 |
| 优化器           | Adam，使用解耦权重衰减          |
| 学习率           | 余弦衰减                   |
| 图像增强          | 缩放后的随机方形裁剪             |
| 投影层           | 线性投影                   |
| 内存与速度优化       | 混合精度、梯度检查点等；相似度计算也进行分片 |

- **RN50x64**：592 块 V100，18 天。

## 七、零样本分类：文本就是可更换的分类器

### 7.1 从类别名称到文本原型

假设下游任务有 $K$ 个候选类别：

$$
\mathcal C=\{c_1,\dots,c_K\}.
$$

先把类别写进提示模板，例如：

```text
a photo of a {label}.
```

再通过文本编码器得到每类的单位向量 $w_k$。

给定图像 $x$，得到单位图像向量 $u$，计算：

$$
z_k=\alpha u^\top w_k,
\qquad
p(c_k\mid x,\mathcal C)
=\frac{\exp(z_k)}
{\sum_{j=1}^{K}\exp(z_j)}.
$$

预测为：

$$
\hat c=\underset{c_k\in\mathcal C}{\arg\max}\ z_k.
$$

因此可以把这些文本向量看成一个动态生成的线性分类器的权重。换类别集合，主要就是换一组文本原型。

### 7.2 “零样本”到底省略了什么

此处的零样本主要指：

**没有使用目标数据集的带标签训练样本来拟合下游分类器或微调模型。**

它不等于：

- 预训练时从来没有见过这个概念。
- 已经排除预训练集与评测集之间的一切图像重叠。
- 推理时不知道候选类别名称。
- 完全没有提示模板设计或研发阶段的评测反馈。

### 7.3 为什么推理可以高效

类别集合和模板固定后，文本向量可以提前计算并缓存。之后每张新图像只需编码一次，再与缓存的文本向量做矩阵乘法。

视频用“向图像问 1,000 次问题”帮助理解 ImageNet 分类，但实现中不需要对每个候选重新运行一遍图像编码器。

### 7.4 开放词汇不等于自动发现所有类别

CLIP 不受固定训练分类头的词表限制，但一次预测仍然需要候选集合。

如果候选中没有正确类别，softmax 仍会在给定选项中分配概率。原始机制不会自动保证返回“以上都不是”。

**整理理解**：这个概率是“当前候选集合内部的相对分配”，不能直接当成校准过的现实正确率。候选集合改变，数值也会改变。

**对应视频**：00:03:52-00:07:20、00:52:21-00:55:44；论文 §3.1.1、§3.1.2。

## 八、提示工程与模板集成

### 8.1 为什么不能只输入类名

视频讲了两个主要原因：

1. **词义可能歧义**：例如 `boxer` 既可能指某种犬，也可能指拳击运动员。
2. **文本分布不同**：预训练配文往往是句子，只输入一个词与训练时的文本形态不同。

因此，提示模板不只是让输入“更像一句话”，也在告诉模型当前任务的语境。

### 8.2 用任务背景缩小歧义

论文举出的做法包括：

- 宠物分类：在描述中说明是一种宠物。
- 食物分类：在描述中说明是一种食物。
- 飞机分类：在描述中说明是一种飞机。
- OCR：为要识别的文字或数字加引号。
- 卫星图像：明确说明这是一张卫星图像。

**整理理解**：模板只能提供上下文，不能保证消除所有歧义；多个候选本身都可能符合“照片里的物体”这一描述。

### 8.3 多模板不是必须重复跑图像网络

论文在 ImageNet 上使用 **80 个上下文模板**。

对类别 $c_k$，设第 $m$ 个模板产生单位文本嵌入 $v_{k,m}$，则原型可写为：

$$
w_k=
\frac{\frac{1}{M}\sum_{m=1}^{M}v_{k,m}}
{\left\|\frac{1}{M}\sum_{m=1}^{M}v_{k,m}\right\|_2}.
$$

官方 notebook 的实际步骤是：

1. 对每个模板编码。
2. 分别归一化文本向量。
3. 在嵌入空间求平均。
4. 对平均向量再次归一化。
5. 缓存每类的最终文本原型。

视频把 ensemble 概括为多次推理再综合。**更精确地说，论文和官方 notebook 在嵌入空间集成，并非必须平均多组 softmax 概率，更不要求每张图像通过图像编码器 80 次。**[^prompt]

论文 §3.1.4 报告：在相应 ImageNet 比较中，单个默认模板相对直接类名提升约 **1.3 个百分点**；80 模板集成再提升约 **3.5 个百分点**，合计接近 5 个百分点。不要把它理解成所有模型和数据集上都固定增加相同幅度。

**对应视频**：00:57:09-01:03:08；论文 §3.1.4、图 4。

## 九、实验：先分清三种评测设置

| 设置                     | 是否使用下游带标签训练样本 | 学习或更新什么          | 主要衡量什么        |
| ---------------------- | ------------- | ---------------- | ------------- |
| Zero-shot              | 不用于拟合下游分类器    | 用文字构造分类器，编码器保持不变 | 语言接口驱动的直接迁移能力 |
| Few-shot linear probe  | 每类少量样本        | 冻结图像编码器，训练线性分类器  | 少样本条件下的表示可用性  |
| Full-data linear probe | 使用下游完整训练集     | 同样只训练线性分类器       | 固定表示的可分性与迁移质量 |
| End-to-end fine-tuning | 使用下游训练样本      | 更新部分或全部骨干参数      | 适配目标任务后的性能    |

**重要区分**：论文 §3.2 的主要表示评测是 linear probe，不是把整个 CLIP 在所有下游数据集上做全参数微调。

### 9.1 ImageNet：76.2% 说明什么

论文表 1 报告，CLIP 的零样本 ImageNet 准确率为 **76.2%**；早期 Visual N-Grams 的相应结果为 **11.5%**。

但论文明确提醒：数据规模、模型架构、单次预测计算和训练计算都不同，**这不是只改变一个算法因素的公平对照实验**。

此外，两种参照不要混为一谈：

- 论文摘要强调，零样本 CLIP 可达到原始 ResNet-50 的准确率量级。
- 论文图 13 的分布偏移对照，选用同为 76.2% ImageNet 准确率的 **ResNet-101**。

### 9.2 27 个数据集：不是处处获胜

论文图 5 比较：

- 零样本 CLIP。
- ImageNet 监督预训练的 ResNet-50 特征，加上下游带标签数据拟合的线性分类器。

CLIP 在 **27 个数据集中的 16 个**上胜出。

其中既有明显优势，也有明显短板：

- 一般物体分类和部分动作、场景相关任务表现较好。
- 某些卫星图像、病理图像、计数、距离判断和细粒度任务表现较弱。
- 细粒度分类内部也有差异，不能一概说“细粒度都不行”或“都很强”。

例如，图 5 中 Stanford Cars 和 Food101 的零样本结果明显优于该 ResNet-50 线性基线，而 Flowers102、FGVCAircraft 则落后。到了与专用强模型比较时，又可能得出不同结论。

### 9.3 为什么给了少量样本，反而不如零样本

论文图 6 的 few-shot 比较采用 **每类至少有 16 个训练样本的 20 个数据集**，不是全部 27 个。

在这个平均口径下：

- 零样本 CLIP 约相当于同一视觉特征上的 4-shot 线性分类器。
- 零样本结果接近评测套件中最好的 16-shot 线性分类器。
- 随着带标签样本增多，CLIP 特征上的线性分类器可以超过零样本结果。

**整理理解**：这里不是“同一个分类器多看了几张图，能力反而退化”。零样本分类器使用文本语义构造权重，few-shot 线性探针则从少量示例拟合权重，两者利用的信息不同。

若一个示例同时包含对象、背景、颜色等多种概念，只有少量图像时，拟合过程未必能准确判断哪个概念才是分类依据。

### 9.4 全量 linear probe：检验视觉表示本身

视频解释，选择线性探针的好处是：

- 冻结骨干后，较能隔离预训练表示的贡献。
- 可调超参数少于全网络微调，便于在大量数据集上采用统一评测流程。

论文图 10 分别展示 12 数据集与更广的 27 数据集评测；横轴是每张图像前向计算的 **GFLOPs**，不是实测延迟。

论文图 11 进一步比较相同线性探针协议下的特征：CLIP 在 **27 个数据集中的 21 个**上优于 Noisy Student EfficientNet-L2。

这支持其表示有较强迁移价值，**不代表零样本 CLIP 在 21 个数据集上击败了所有全监督最优模型**。

**对应视频**：00:55:47-00:57:06、01:03:26-01:15:18；论文表 1、图 5、图 6、图 10、图 11。

## 十、鲁棒性：更能迁移，不是没有分布偏移

视频用真实照片、绘画、素描等形态中的相同对象说明跨域识别。

论文 §3.3、图 13 的关键问题是：

**在原始 ImageNet 准确率相近时，换到自然分布偏移数据，哪个模型保留的识别能力更强？**

图 13 右侧报告的部分结果如下，单位为准确率百分比：

| 评测数据            | ImageNet ResNet-101 | 零样本 CLIP |
| --------------- | ------------------: | -------: |
| ImageNet        |                76.2 |     76.2 |
| ImageNetV2      |                64.3 |     70.1 |
| ImageNet-A      |                 2.7 |     77.1 |
| ImageNet-R      |                37.7 |     88.9 |
| ObjectNet       |                32.6 |     72.3 |
| ImageNet Sketch |                25.2 |     60.2 |

**读表边界**：这些数据集的类别范围、样本难度和评测处理并不相同。不能把每行与完整 ImageNet 分数简单相减，当成严格同口径的“性能下降”；图中的香蕉图片也是示意样例，不表示表内只统计香蕉一类。ImageNet-A 指特定自然对抗样本基准，不等同于任意人为生成的像素对抗攻击。

更合适的结论是：**相对于同等 ImageNet 表现的监督模型，零样本 CLIP 在这些分布偏移基准上表现更强。**

视频中的“基本没掉点”属于概括性表达，不能当作对所有域的保证。下文 MNIST 的例子正说明，CLIP 仍然会在其预训练覆盖不足的分布上失败。

**对应视频**：00:07:33-00:09:07、01:15:20-01:16:00；论文 §3.3、图 13。

## 十一、人类比较与数据重叠

### 11.1 人类实验能说明什么

论文 §4、表 2 在 Oxford-IIIT Pets 上比较了 37 类宠物识别。5 名参与者分别在没有示例、每类 1 张示例、每类 2 张示例的条件下完成任务。

表中的**平均每类准确率**为：

| 设置 | 准确率 |
| --- | ---: |
| Zero-shot human | 53.7% |
| One-shot human | 75.7% |
| Two-shot human | 75.7% |
| Zero-shot CLIP | 93.5% |

这不是“CLIP 全面超越人类视觉”的证据。它只对应一个特定数据集、一种识别任务和有限参与者。

视频据此讨论人类如何利用先验知识快速理解示例。可以保留这个启发，但不能据此断言“人类多看样本没有用”：该实验只测了有限条件，人类参考示例的方式也与线性分类器训练不同。

### 11.2 零样本不自动排除数据污染

视频在 01:20:03 左右简要提到训练集与评测集重叠，没有展开全部细节。

**论文补充核查，§5**：作者不是先保证所有未来评测集都已去重，再完成训练；而是使用重复检测器，将评测样本划为 `Overlap` 与 `Clean` 子集，分析重叠及准确率变化。

该分析发现，已检测重叠对整体结果的影响通常较小。但检测器的召回率无法在 4 亿样本上完整验证，子集的难度与分布差异也可能影响比较。

因此应表述为：

**论文进行了重叠审计，结果不支持“全部迁移效果只是重复记忆”的简单解释；但没有证明所有污染风险都已彻底消除。**

**对应视频**：01:16:17-01:20:31；论文 §4、§5、表 2。

## 十二、最值得精读的部分：局限性

视频用了较长篇幅讨论论文 §6。这个部分能防止把前面的亮眼结果理解成“万能视觉模型”。

### 12.1 与简单基线竞争，不等于达到所有任务的最优

零样本 CLIP 平均可以与简单的 ResNet-50 线性基线竞争，但该基线并非多数任务的最强模型。

论文按当时的缩放趋势估计，要单靠扩大规模追到整体最优水平，可能需要约 1,000 倍计算。这是论文当时的外推估计，不是永恒的计算下界，也不是后来所有模型都必须承担的成本。

### 12.2 抽象、系统性和专业任务仍然困难

计数、距离判断、部分专业图像和细粒度任务，不能仅凭“图文语义相近”就可靠解决。

视频还举了异常/安全判别作为讨论例子；它不是本文已系统报告的统一异常检测实验结果。

### 12.3 大规模数据不保证覆盖所有分布

论文报告零样本 CLIP 在 MNIST 手写数字上只有 **88%**，低于直接在像素上训练逻辑回归的简单基线。

作者检索预训练数据后发现，几乎没有与 MNIST 数字相似的图像。

**术语核查**：MNIST 是手写数字数据，不应沿用视频中“合成数据”的泛化称呼。这里要强调的是其分布与常见互联网自然图像不同，而不是把它归为程序合成图像。

### 12.4 能选候选，不代表会生成答案

原始 CLIP 做的是图文编码与相似度比较，不直接生成 caption，也不直接输出任意自然语言回答。

图像生成应用中，可以使用 CLIP 的匹配信号指导另一个生成或优化过程；生成图像的不是 CLIP 自身。

### 12.5 减少人工标注，不等于数据利用高效

4 亿图文对训练 32 轮，约为 **128 亿次图像展示**，不是 128 亿张不同图像。

论文用“每秒看一张，需要约 405 年”说明数据量之大，不是在报告实际训练耗时。

### 12.6 零样本评测也可能受到研发反馈影响

**论文原文核查，§6**：作者承认研发过程中反复查询了完整的 **validation sets，验证集** 表现，并且主要评测套件与模型开发存在共同适应的可能。

视频口述多次说“测试集”；笔记在此采用论文的“验证集”表述，**不据此进一步指控作者反复使用官方隐藏测试集调参**。

这个问题与训练样本重叠不同：即使图像没有重复，反复根据同一批基准反馈改方法，也可能使评测不再完全独立。

### 12.7 社会偏见和使用风险没有自动消失

互联网图文数据可能携带偏见。能够自由定义类别，也意味着用户可能构造不恰当的分类问题。

视频介绍了监控检索的成功示例，也提醒成功展示不代表全面可靠。正文未详细讲解论文 §7 的全部偏见实验，因此这里不把它包装成已完整复述的章节。

### 12.8 自然语言接口与 few-shot 学习仍需结合

部分复杂概念不容易只靠文字说清楚，真实示例依然重要。论文采用的少样本线性探针没有充分结合零样本文本分类器中的先验。

**整理理解**：值得研究的是如何把文本给出的语义、图像示例和原有视觉表示结合起来，而不只是分别使用两套分类器。

**对应视频**：01:20:34-01:30:33；论文 §6。

## 十三、后续应用：借用 CLIP 的语义接口

视频开头介绍了若干应用方向。这些是对 CLIP 价值的延伸展示，**不是原始 CLIP 在不改结构、不加组件的情况下直接完成所有任务**。

| 方向        | 视频中的解释                | 需要保留的边界                   |
| --------- | --------------------- | ------------------------- |
| StyleCLIP | 用文字引导 StyleGAN 图像属性编辑 | 依赖生成模型及相应编辑方法             |
| CLIPDraw  | 用图文相似度指导绘图参数优化        | 绘图由额外表示和优化过程完成            |
| 开放词汇检测    | 利用语言表示扩展检测类别          | 原始 CLIP 不直接输出目标框，需要检测方法适配 |
| 视频检索      | 把文本与视频帧表示比较，寻找相近内容    | 个别成功片段不等于跨视频的完整检索评测       |

本次未逐篇核查这些后续工作的全部论文和实验，保留为**视频介绍的研究方向**，不补造未确认的检测论文名称或统一性能结论。

**对应视频**：00:09:09-00:14:09。

## 十四、红包演示：既展示能力，也暴露候选集限制

视频最后使用较小的 ViT 基础模型做了一个红包图片分类演示，而非论文默认的最大模型。

过程大致为：

1. 先提供与图片不相符的候选，模型仍然在这些选项之间分配分数。
2. 加入 `red envelope` 后，模型将其选为最高分候选。
3. 再加入 `red`、`envelope` 等描述，观察具体概念与属性的竞争。
4. 加入 `money`、`new year`、`china` 等关联词。
5. 去掉 `red envelope` 后，该示例的最高分候选转向 `china`。

可以得到的观察是：

- 候选类别可以在推理时直接更换。
- 同一图像可能与具体物体、属性和文化关联等多类文本相关。
- 相似度最大，不必然表示找到了正确粒度的“物体类别”。

不能据此证明：

- CLIP 已全面理解红包背后的文化、因果关系或使用场景。
- 显示接近 100% 的 softmax 数值，就代表经过校准的 100% 正确率。
- 去掉正确选项后，模型会主动承认不知道。

**整理理解**：这是一个很好的机制演示，不是统计实验。需要在更多图片、不同提示和更强干扰候选上系统验证，才能讨论稳定的识别能力。

视频末句在当前字幕中没有完整结束，本节只归纳已出现的操作和现象，不代替讲者续写结论。

**对应视频**：01:34:40-01:38:26。

## 十五、读完后应记住的六件事

1. **监督形式改变了**：从固定类别标签，转向可扩展的图文配对。
2. **核心训练目标很简洁**：双编码器、共享嵌入空间、批内图文匹配、双向交叉熵。
3. **零样本能力来自语言接口**：文本编码器把类别描述转成分类器权重。
4. **提示模板是任务定义的一部分**：上下文与候选集合会改变分类结果，集成可以在文本嵌入空间完成。
5. **实验结果必须连同口径阅读**：zero-shot、few-shot linear probe、全量 linear probe 和全参数微调不是同一件事。
6. **迁移很强不等于万能**：真实分布外数据、抽象任务、数据污染、评测共同适应和社会偏见仍然需要单独审计。

用一句话总结：

**CLIP 用可扩展的图文对比预训练，学到可由自然语言调用的视觉表示；它突破了固定分类头的限制，但没有取消候选设计、数据覆盖和严格评测的重要性。**
