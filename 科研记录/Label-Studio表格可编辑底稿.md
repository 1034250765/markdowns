## 表 06 功能可行性与版本限制

> 对应正文：4.1 功能与限制

| 评估项 | 核查结果 | 对本项目的影响 |
|---|---|---|
| 整牛目标检测框 | 官方提供 `Image` + `RectangleLabels` 模板 | 可以作为主任务界面［O3］ |
| 水平框约束 | `RectangleLabels` 可通过 `canRotate="false"` 隐藏旋转控制 | 项目按水平框配置；导出仍检查角度［O4］ |
| 模型预标注 | 支持 `data` + `predictions` JSON，经 UI 或 API 导入 | 可以复用离线 YOLO 预测［O2，O8］ |
| 本地图片引用 | 官方提供 Local Files Storage 与 `/data/local-files/?d=...` | 适合服务器图片就地访问［O1］ |
| 多人协作 | 社区版可多人参与，但全部用户可看到全部项目 | 仅适合可信的小团队；权限隔离需另行评估［O10］ |

| 标注速度与质量 | 本次无计时或一致性实测 | 只能得出技术可行，不能宣称效率或精度提升 |

## 表 07 标注路线比较与选择

> 对应正文：4.2 三种路线的取舍

| 路线 | 实施方式 | 适用场景 | 主要成本 | 本次建议 |
|---|---|---|---|---|
| A. 纯人工 | 导入图片，逐图画框 | 小批量、预标注很差、困难样本 | 画框耗时较高 | 保留为基线和备用路线 |
| B. 离线预标注 + 人工修正 | 独立运行 YOLO，转 JSON 后导入 | 固定批次、已有可用检测模型 | 转换与复核；可能受模型偏差影响 | **优先小规模试用** |
| C. 在线 ML backend | 标注时请求模型服务 | 频繁迭代、交互预测需求明确 | 模型服务、网络、认证和维护 | 后续再评估 |

## 表 08 牛只水平框标注规则

> 对应正文：5.1 先固定标注规则

| 情况 | 拟议规则 |
|---|---|
| 目标类别 | 一头牛一个 `Cow` 框；不把人、栏杆、牛头或牛背单独作为整牛目标 |
| 框的类型 | 轴对齐水平框，`rotation=0`；本记录不处理 OBB、分割或关键点 |
| 框的范围 | 尽量包围该牛可辨认的可见部分；不凭空扩展被遮挡的身体范围 |
| 多牛遮挡 | 能分辨为不同个体时分别标；边界有争议时进入复核 |
| 画面截断 | 以画面内可见部分为准，框不得超出图像 |
| 极小、过暗或无法判断 | 记录为难例，提交裁决；不能静默漏掉或自行宣布无牛 |
| 真正无牛的图片 | 经人工确认后可作为负样本；保留“已检查”的记录 |
| 模型没有检出 | 仍需逐图检查，不等于负样本 |

## 表 14 现象、证据与排障措施

> 对应正文：7. 常见问题与旧指南的适用边界（Troubleshooting）

| 现象 / 旧说法 | 本次核查后的判断 | 建议处理 |
|---|---|---|
| 图片 401 / 403 | 可能与登录、权限、文件服务设置有关，不能仅凭状态码确定唯一原因 | 登录后查看网络请求与后端日志；核查两个环境变量 |
| 图片 404 | 可能涉及路径、文件权限、存储注册、软链接或挂载 | 对照 `DOCUMENT_ROOT`、存储目录、URL 的 `d` 参数逐层核查［O1］ |
| `data` 中出现 `$undefined$` | 本地曾记录该异常；任务数据字段应与标签配置对应 | 检查 XML 与导入方式；暂停继续同步，不直接批量删库［L1，O2］ |
| “Sync 一定会造坏任务” | 不能推广；官方提供 Files / Tasks 等同步路径 | 本 SOP 手动导入 JSON 时只保存媒体连接，避免再建一批图片任务［O1］ |
| “Local Storage Path 填相对目录即可” | 旧实例笔记与当前 UI 文档表述不同 | 当前文档使用绝对目录；`d=` 才使用相对根目录路径，旧界面先试连接［L1，O1］ |
| “1.23 没有公开 API” | 错误泛化；公开导入端点和对应版本源码均存在 | 按 PAT / legacy 区别检查认证、项目权限和请求格式［O7，O8，O18］ |
| 预标注框不能编辑 | prediction 按官方设计为只读 | 创建或复制为 annotation 后再修改［O2］ |
| `cow` / `Cow` 同时出现 | 映射不一致，不能默认视为同一类别 | 统一明确映射，核对导入和导出类别表［L3］ |
| 导出后图片缺失 / 标签配错 | 不能假定所有格式都打包图片；URL 与文件名也可能不同 | 用来源清单配回原图，保留路径并正确处理 URL 编码［L3，O11］ |
| 页面筛选后仍导出其他任务 | 当前社区版 UI 导出有范围限制 | 原生导出后与批准清单对账；必要时评估 SDK / API［O11］ |
| 直接 SQLite 修复最快 | 数据表和关联约束依赖具体版本，直接写库风险较高 | 日常使用 UI / API；复杂修复交管理员先备份和验证 |
| 导出成功即能开始训练 | 只说明产生文件，不能证明标签正确、划分合理 | 完成数量、类别、坐标、负样本和可视化验收 |
