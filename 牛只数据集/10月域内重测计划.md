## 一、背景与目标

文章初稿 4.3/4.4 节的域内结果存在三类问题，不能作为正式结果：

1. **参数不统一**：YOLO11m 首批 3 个数据集 batch=16、其余 11 个 batch=32；AMP 各模型不一致（YOLO11m 开、其余关）；`optimizer=auto` 各自选择；MMDet 有效 batch 两种实现；训练中途 torch 环境变更（2.6.0+cu118 → 2.5.1+cu124）。
2. **无独立测试集**：全部结果在各数据集 `val` 上评测（Dairy Cow 的名义 `test` 别名实际指向 `val`）。
3. **数据版本旧**：训练数据为 self_mAP 时代划分（23,851/4,971/2,551），未经 2026-09 的 SHA-256 去重与 8:1:1 重切。

本轮目标：**在权威数据 `data/` 上，以与 LODO 冻结协议对齐的统一训练协议，为 14 个数据集重建域内参照 $M_{t\to t}$（test 冻结视图）**，一次性解决上述三个问题。

本轮范围：**仅 YOLO11m、单种子 seed=42**（2026-10-05 决定）。四架构（RT-DETR-L / Faster R-CNN / RetinaNet）与 YOLO11s/l 的统一复核不在本轮，另行排期。

产出的 $M_{t\to t}$ 同时服务三处：

1. LODO 对比（LODO测试-9月.md 后续工作 1）：目标域归一化保持率 $R^{LODO}_{target}(t)=M_{-t\to t}/M_{t\to t}$；
2. 文章 4.5 节目标域归一化保持率的分母（与 LODO 目标视图同源同协议）；
3. 文章 4.3 节 YOLO11m 列的 test 口径正式结果。

## 二、实验定义

对 14 个数据集 $t$（8-calves、animals_10、CBPD_ODD、CID、CImage、COCO、COLO、Cows2021、diarycow、Google_Open_Images、HCRD、MooTrack360、NWAFU_CD、XGain）：

- **训练**：`data/<t>/train` 全量（不含跨源配额抽样）；
- **验证**：`data/<t>/val`，每 epoch 一次，是 checkpoint 选择的唯一依据；
- **测试**：`data/<t>/test` 冻结视图，仅在 checkpoint 选定后评测一次。

$$M_{t\to t}=\operatorname{Eval}\big(\operatorname{Train}(D_t^{train})\,;\,D_t^{test}\big)$$

test 视图与 LODO 目标域冻结视图为同一套 `images/test`（总计 3,124 张，逐数据集图像数一致），评测代码逐项一致（第五节），因此 $M_{t\to t}$ 与 $M_{-t\to t}$ 直接可比。

## 三、训练协议（冻结，14 个数据集一致，不得按数据集调整）

| 项目 | 值 | 与 LODO protocol.yaml 对照 |
|---|---|---|
| 检测器 | YOLO11m，nc=1 `cow` | 同 |
| 初始化 | `lodo/yolo11m.pt`（同一份固定权重，md5 记录于 run_info） | 同一份文件 |
| imgsz | 640 | 同 |
| epochs | 100（patience=100，不触发早停） | 同 |
| batch / nbs | 16 / 16 → **accumulate=1**（on_train_start 断言核验） | 同 |
| 优化器 | **AdamW、lr0=0.002**（显式固定，禁止 auto） | 同 |
| AMP | True | 同 |
| 数据增强 | Ultralytics 默认（close_mosaic=10 等） | 同 |
| 随机种子 | 42（仅训练层；无抽样层） | LODO 主方案同为 42 |
| 末 batch | **保留**不足 16 张的末批（stock `drop_last=False`，`compile=False` 下成立，断言核验） | 同规则 |
| 保存 | save_period=1，每 epoch 一个 checkpoint，保存后剥离优化器状态 | 同 |
| 每 epoch 验证 | 本域 `val`（stock 行为，results.csv 完整记录） | LODO 为 13 源分域宏平均 |
| 训练池 | `data/<t>/train` 全量 $N_t$ 张，每 epoch $\lceil N_t/16\rceil$ 步 | LODO 为 13 源 × q=500 |

**与 LODO 的三项已知差异（声明性差异，非对齐失误）：**

1. **训练池**：域内参照按定义即目标域监督训练（9月计划 6.1 节 $M_{t\to t}$），不含跨源等权配额；每 epoch 优化步数随数据集规模不同（LODO 恒 407 步）。
2. **洗牌种子规则**：stock 的 seeded generator 逐 epoch 洗牌（LODO 的 `seed×1048576+epoch` 规则是其"每 epoch 重建 loader"的实现产物）。两者均确定可复现，超参层面无差异。
3. **验证构成**：本域 val 单曲线（LODO 为 13 源分域验证取宏平均）。

## 四、checkpoint 选择规则

$$e^*=\arg\max_e\; \text{val mAP@0.5:0.95}(e)$$

- 依据 `runs/train/results.csv` 的 `metrics/mAP50-95(B)` 列；**并列取较早 epoch**（严格 `>` 升序遍历实现）；
- stock `best.pt` 按综合 fitness 保存、并列时保留较晚 epoch，仅是副产物，**不作为选择依据**；
- 第 100 epoch checkpoint（`epoch100_final.pt`）作为固定预算敏感性对照；
- **test 不参与选择**；test 评测在全部 14 个数据集的 selected.pt 确定后统一执行。

## 五、评测协议（与 lodo_eval_target.py 逐项一致）

- `YOLO(ckpt).val(data=data/<t>/data.yaml, split="test", imgsz=640, device=0, plots=False)`；
- Ultralytics 默认评估器与 NMS，不做任何调参；
- 评测对象：`selected.pt` 与 `epoch100_final.pt`（敏感性对照）；
- 记录字段：mAP@0.5、mAP@0.5:0.95、P、R、test 图像数与实例数（与 `lodo_target_test_results.csv` 同构）；
- 评测前后断言 test 图像数与 `data/README.md` 数据集构成表一致。

## 六、质量核验（全程生效的断言与检查）

- on_train_start：`accumulate==1`、`nbs==batch==16`、`optimizer=='AdamW'`、`lr0==0.002`、`amp==True`、`compile==False`（drop_last 前提）、`resume==False`、`train_loader.drop_last==False`；
- 数据规模：train_loader 图数与 `splits/<t>/train.txt` 行数断言一致；
- run_info.json：协议快照、初始化权重路径与 md5、ultralytics/torch/CUDA 版本、GPU 型号、每 epoch 理论步数、开始时间；
- 驱动器：严格串行（flock 防双开）、`results.csv` 满 100 行视为完成并跳过、崩溃自动从头重跑（最多 3 轮）；
- 冒烟测试：正式运行前以 CImage + 2 epochs 验证断言、保存、剥离、选择、评测全链路，验证后删除 smoke 产物。

## 七、产出与分析

1. `indomain/results/indomain_test_results.{csv,json}`：14 域 × {selected, epoch100} 全指标；
2. $R^{LODO}_{target}(t)$：逐种子（42/43/44）与三种子均值两套口径；
3. 14 域等权宏平均与 selected vs epoch100 敏感性；
4. 与 7 月旧 val 口径结果的**描述性**对照表（数据版本、划分、协议、评测视图均不同，不作可比性结论）；
5. $\Delta_{multi}(t)$（相对 14×14 单源迁移均值）**不在本轮范围**：现有 14×14 矩阵基于旧数据/旧视图，需另行同视图重评后方可计算。

## 十、结论边界

- $M_{t\to t}$ 是目标域监督训练参照，**不是理论上限**；$R^{LODO}_{target}>1$ 不裁剪、不异常化；
- 单种子结果；种子稳定性参照 LODO 经验（跨轮 SD 0.0019）再决定是否补 43/44；
- CImage（17 张）、CBPD_ODD（36 张）等小 test 集方差大，跨数据集比较必须注明样本量；
- 本轮结果与 2026-07 旧域内结果**不可直接比较**（数据版本、划分、协议、评测视图全部不同），旧表仅作历史记录；
- 域内高 mAP 不构成数据集质量排名，也不预测跨域泛化能力（文章 4.5.1 已有证据）。
