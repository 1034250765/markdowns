## 一、实验概述

本实验执行《10月域内重测计划》：在权威数据 `data/`（SHA-256 去重 + 8:1:1 划分）上，以与 LODO 冻结协议对齐的统一训练协议，为 14 个数据集重建域内参照 $M_{t\to t}$（**test 冻结视图**）。

解决的三个旧问题：**参数不统一**（统一为 LODO 协议）、**无独立测试集**（全部改用 test 冻结视图）、**数据版本旧**（全部在 `data/` 上重训）。

范围：**YOLO11m ×14**。除主方案（seed=42）外，另执行两轮完整重复（train_s43、train_s44）与一次同 seed 判别实验（HCRD），用于**运行间稳定性验证**（第五节；因本协议下 seed 值为空操作，重复轮以 seed 命名仅是沿用 LODO 惯例，其实际作用等同独立重复运行）。四架构与 YOLO11s/l 复核另行排期。**种子重复扩展**（es 协议，三种子 42/43/44，2026-10-09 至 10-12）见第十一节。

## 二、训练与评测协议（冻结）

### 2.1 训练协议（14 个数据集一致，不得按数据集调整）

- YOLO11m、单类别 `cow`、imgsz=640、100 epochs、AMP；
- batch=16、**nbs=16 → accumulate=1**（on_train_start 断言核验）；
- **AdamW、lr0=0.002**（显式固定，禁止 auto），其余超参 Ultralytics 默认；
- 训练池 = `data/<t>/train` 全量；**末 batch 不足 16 张保留**（drop_last=False 断言核验）；
- 初始化 = `lodo/yolo11m.pt`（与 LODO 全部 fold 同一份权重，md5 `2c2bcbb54c3829b20d31a32524ee0f03`）；
- 随机性：`seed=42`（主方案）、`deterministic=True`；重复轮 seed=43/44（第五节证实 seed 值不影响训练过程）。

与 LODO 的三项声明性差异（计划第 3 节）：训练池为单域全量（非 q=500 配额）、stock seeded 洗牌、验证为本域 val 单曲线。

### 2.2 checkpoint 选择规则

$e^*=\arg\max_e$ 本域 val mAP@0.5:0.95，**并列取较早**（严格 `>` 升序遍历）；依据 `runs/train/results.csv`；stock `best.pt`（fitness 口径、并列取较晚）仅是副产物，不作依据；第 100 epoch checkpoint（`epoch100_final.pt`）作固定预算敏感性对照；**test 不参与选择**。

### 2.3 评测协议（与 lodo_eval_target.py 逐项一致）

- `YOLO(ckpt).val(data=data/<t>/data.yaml, split="test", imgsz=640, device=0, plots=False)`；
- Ultralytics 默认评估器与 NMS，不做任何调参；
- test 冻结视图只在最终评测出现一次，不参与训练、验证、早停与 checkpoint 选择；
- 记录 mAP@0.5、mAP@0.5:0.95、P、R、test 图像数与实例数。

### 2.4 质量核验（全程生效）

- 14/14 run 的断言链全部通过（accumulate=1、末批保留、splits 清单一致性）；
- 14/14 `results.csv` 满 100 行；每 epoch checkpoint 存在且已剥离优化器（40.5MB）；
- 评测前后 test 图像数与 `data/README.md` 构成表逐数据集断言一致（合计 3,124）；
- 选择规则仅用 val 指标；`selection.json` 存档各域 e*、val 峰值与并列情况；
- 受事故影响的两个数据集经恢复重训与三重核验（3.5）。

## 三、工程实现与执行事件

### 3.1 脚本与断言链

训练脚本 `indomain_train.py`（YOLO + 回调，非子类化）：`on_train_start` 断言链（accumulate=1、nbs=batch=16、AdamW@0.002、AMP、compile=False、drop_last=False、train 图数与 `splits/<t>/train.txt` 一致）+ `run_info.json`（协议快照、权重 md5、环境版本）；`on_model_save` 每 epoch 保存后剥离优化器。运行名按 seed 自动派生（`train` / `train_s<seed>`），危险组合（`--run-name train` × seed≠42）硬报错（3.4 事故后加固）。

### 3.2 实现前的源码级核验（Ultralytics 8.4.92）

| 疑点                                 | 结论                                                                                                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| stock 训练 loader 是否丢末批              | `drop_last = args.compile and mode=='train'`，compile=False 下恒保留 ✓                                                                         |
| plots=False 是否影响 results.csv       | `save_metrics` 无条件执行，仅出图受 plots 控制 ✓                                                                                                      |
| on_train_start 时 train_loader 是否已建 | `_setup_train()`(L390) 先于 `run_callbacks("on_train_start")`(L398) ✓                                                                       |
| strip_optimizer 与 ckpt 内部 epoch    | 剥离时内部 epoch 置 -1，不能用于核验文件名映射（映射沿用 LODO 生产约定：results.csv 1-based e ↔ `epoch{e-1}.pt`）                                                      |
| `sum(nt_per_image)` 语义             | 实为"含目标的图像数"（`target_img=np.unique(cls)`）；真实实例数在 `nt_per_class.sum()`。`lodo_eval_target.py` 的 `test_instances` 列自始记录的是前者（无下游引用，无实害）；本实验已修正 |

## 五、可复现性与运行间稳定性

### 5.1 机制：seed 在本协议下是空操作

三条随机性通道全部关闭（Ultralytics 8.4.92 源码 + 实验证实；前期曾误判 seed 会影响头部初始化，经源码核查更正）：

1. **模型初始化**：`cls_remap` 将 nc=80 预训练头**确定性通道重映射**到单类（日志 `Transferred 649/649 items`，无任何随机初始化层）；
2. **数据管线**：`build.py` 的 loader generator 为固定常数 `6148914691236517205 + RANK`，与用户 seed 无关 → 洗牌顺序与 worker 增强 RNG 均不随 seed 变化；
3. **CUDA 非确定性**：`deterministic=True` 压制。

直接证据：8-calves 在 seed=42 与 seed=43 下的 100 epoch val 曲线逐行完全一致。因此本节的"三轮重复"应表述为**运行间稳定性**而非"种子稳定性"——seed 值本身无作用，重复轮等价于独立重复运行。

### 5.2 三轮完整重复的逐域一致性（test 口径）

| 重复轮 ① | 100 | 0.91925 | 0.94598 |
| 重复轮 ② | 96 | 0.92568 | 0.93760 |
| 同 seed 重跑 | 98 | 0.92888 | 0.92850 |

### 5.4 运行间噪声的定量与报告口径

- 三个噪声域的 test 级运行间不确定性：**CBPD_ODD ±0.008 / COLO ±0.003 / HCRD ±0.010**（三轮极差）；HCRD 的 val 峰值与 test 表现存在解耦（106 张小集合加剧波动）；
- 11/14 域完全逐位可复现可作为协议性质写入文章；
- 噪声域的 $M_{t\to t}$ 与 $R_{target}$ 引用时注明运行间不确定性区间；
- 主表（4.2）数字为主方案（seed=42）口径，不因重复轮改动。

## 八、初步观察（描述性，不作因果解释）

1. **$R_{target}$ 呈清晰分层**：开放/混合来源域（CBPD_ODD 0.994、animals_10 0.994、COCO 0.970、Google 0.933、CID 0.843）上，13 源联合训练几乎达到域内监督水平；设置特异的固定机位域保持率显著更低（MooTrack360 0.208、Cows2021 0.300、HCRD 0.307、COLO 0.586、8-calves 0.588、XGain 0.673、NWAFU 0.679、diarycow 0.697）。
2. **与 14×14 方向性观察互补**：旧矩阵中"G3→G1/G2 强、反向弱"以源域归一化报告；本表以目标域自身监督为分母复核了同一方向——高设置特异性域的域内优势主要来自设置特化，多源训练难以零样本替代。
3. **CImage $R_{target}=1.486$**：141 张训练图的域内微调反而低于 13 源联合训练（0.482 vs 0.717），也与文章 4.5.4"单源微调多数不超过预训练参照"（CImage 预训练参照 0.777）一致——小样本微调伴随特化甚至退化。$R>1$ 按协议不裁剪、不异常化。
4. **域内绝对水平与保持率无关**：Cows2021 域内 0.888（第 4 高）但 $R$ 仅 0.300；CBPD_ODD 域内 0.908 且 $R$ 0.994。域内 mAP 不预测"多源训练能否覆盖该域"。
5. **可复现性**（第五节）：11/14 域三轮逐位一致；CBPD_ODD/COLO/HCRD 存在 ±0.003–0.010 的运行间噪声；$R_{target}$ 宏平均在单轮/多轮口径下稳定于 0.733±0.001。
6. diarycow 域 P=0.9942、R=1.0000，test 接近饱和；小 test 集（CImage 17、CBPD_ODD 36）指标方差大，比较须注明。

## 十一、种子重复扩展（es 协议，2026-10-09 至 10-12）

### 11.1 动机与协议

第五节证实 stock 协议下 seed 为空操作——`build_dataloader()` 的 loader generator 是固定常数（`manual_seed(6148914691236517205 + RANK)`），与用户 seed 无关，故 train_s43/train_s44 只是重复运行，主实验缺少训练随机性方差的量化。为补齐该证据，2026-10-09 制定 **es（effective-seed）扩展协议**并冻结（计划文档第十一节）：在第二节协议全部超参不变的前提下，唯一差异为以子类替换 `ultralytics.data.build.InfiniteDataLoader`，把 loader generator 覆盖为按创建顺序由 seed 派生（seed+0、seed+1、…）。

源码核验（8.4.92 + torch 2.5.1，服务器实测）确认覆盖一处即同时激活两条通道：torch `DataLoader.__init__` 把该 generator 传给 `RandomSampler`（`_RepeatSampler` 逐 epoch 重新 randperm，洗牌），`_BaseDataLoaderIter` 又从同一 generator 抽 worker base seed（`seed_worker` 据此设 np/random/torch，增强）；第三条通道（`cls_remap` 初始化）本就确定性，不受影响。

工程实现与验证（全部通过）：

- 开关 `--effective-seed`：默认关闭，关闭时与冻结协议逐位一致（冒烟 smoke_stock 与冻结 train 第 1 epoch 逐位相同）；运行名 `train_es<seed>`，硬报错禁止写入 `train`/`train_s<N>` 冻结目录；
- 审计材料：每 run `seed_loader_creations.json`（loader 派生种子：train=seed+0/shuffle=True、val=seed+1/shuffle=False）与 `run_info.json` 的 `effective_seed`/`seed_patch` 字段；
- CPU 机制测试（`indomain_seed_patch_test.py`）：同 seed 两次运行顺序逐位一致、异 seed 第 1 epoch 即分叉、逐 epoch 洗牌、worker RNG 随 seed 分离、stock 对照不变；
- 端到冒烟（CImage × 2 epochs × 4 运行）：es42 两次逐位一致、es42 vs es43 第 1 epoch 分叉（val mAP50 0.299 vs 0.703）、stock 路径复现冻结结果。注：冒烟第 2 epoch 与冻结 train 不同属预期——warmup 目标 lr = lr0×lf(epoch)，lf 随总 epochs 衰减（epochs=2 时第 2 轮目标减半），与 seed/patch 无关，正式 100-epoch 运行不存在该效应。

### 11.4 结论与边界

1. **主表对训练随机性稳健**：es 三种子宏平均 0.7205 ± 0.0016，与 stock 主方案 0.7214 差 0.0009；14 域种子 SD 中位数 0.0033，10/14 域 ≤ 0.004。文章可声明"域内参照对训练随机性稳健（三种子宏平均 SD 0.0016）"。
2. **小样本域种子方差最大**：CImage ±0.0182（17 张 test）、Google ±0.0082，与第七、八节的小样本不稳定观察一致。
3. **与第五节互补而非重复**：stock 三轮刻画同 seed 运行间非确定性（11/14 逐位一致 + 3 噪声域 ±0.003–0.010），es 三轮刻画跨 seed 训练随机性（14 域全部有差异）。两个不确定性来源分别量化；两套数字协议不同，不可混写。
4. **HCRD 位置备注**：stock 主方案 0.9468 高于 es 三值（0.9361–0.9439）上端，方向与 5.4 节"主方案恰为四次 stock 运行中最高"一致；引用 HCRD 保持率时注明分母可能偏乐观。
5. **边界**：SD 为 n=3 描述性离散度，不构成置信区间；es 不替换主表（主表仍为 stock seed=42 口径）；es 轮 checkpoint 选择与评测协议与主实验逐项一致（同脚本、同规则），test 隔离链不变。
