## 五、固定阈值评测与三个问题的排查（09-05 ~ 09-06，核心工作）

### 5.1 任务

按新协议重评四架构 P/R/F1：**主结果 = 统一固定置信度阈值 conf=0.25、IoU≥0.5 一对一匹配；补充结果 = 验证集最佳 F1 阈值**；mAP 由评估器在置信度扫描下计算；NMS IoU 阈值、最大检测数和后处理规则固定并记录。前置检查确认：28 个 Ultralytics run 中 25 个 fitness-best 轮 == mAP 最高轮，可直接用 `best.pt` 重测（3 个不一致的轮间 mAP 差 ≤0.0009，噪声级）。

### 5.2 问题一：predict 默认 rect=True（边缘效应）

**现象**：`evaluate_yolo_pr.py` 重测的 P/R 比 Ultralytics 训练记录低 4~5 个点（8-calves：0.924/0.897 vs 0.963/0.951）。

**排查**（自底向上逐层排除）：图片 md5 一致 → GT 逐框一致（1633=1633）→ cv2/PIL 像素零差异 → dataset 输出张量与手动 letterbox 零差异 → 单图预测框正常。最后在问题图上发现：**GT3 的最佳预测 IoU=0.897 但 score=0.002** ——位置对、分数系统性崩溃，指向预处理边界条件。

**根源**：Ultralytics 8.4.92 的 predictor **默认 `rect=True`**：`pre_transform` 输出自动矩形输入（如 800×600 图片为 480×640，无填充），而训练验证的 dataloader letterbox 输出 640×640 正方形。密集俯拍场景中大量目标贴着图像边缘，无填充输入的边界卷积响应弱，边缘目标置信度系统性下降。

**修复**：评测脚本显式 `rect=False`（验证：单图预测框数、分数与手动复刻 validator 链完全一致）。

### 5.3 问题二：匹配顺序语义（最隐蔽，影响最大）

**现象**：rect 修复后仍有差距；RT-DETR 最严重——CBPD_ODD 92 个 GT 在 thr=0.05 只匹配 82 个，而 Ultralytics 评估器给 92 个（全部）。

**排查**：同一批预测、同一批 GT、IoU 矩阵数值一致（vs torchvision 差 <1e-6），直接调用 Ultralytics 的 `match_predictions` 与自写 `match_image` 对比，TP 差 10 个，锁定匹配实现。

**根源**：8.4.92 `match_predictions`（非 scipy 路径）的两步去重：

```python
matches = matches[iou降序]
matches = matches[np.unique(matches[:,1], return_index=True)[1]]  # unique pred
matches = matches[np.unique(matches[:,0], return_index=True)[1]]  # unique gt
```

索引数组**不排序**直接使用——unique 的输出按值升序排列，而预测按分数排序（pred 索引升序 = 分数降序），两步组合的隐含语义是：**同一 GT 的多个重复检测保留分数最高的预测**。我最初按"IoU 降序"实现（并加了 `np.sort` 保持 IoU 顺序），让高 IoU 但低分的重复框抢走 GT 绑定——固定阈值统计时这些低分 TP 全部丢失。RT-DETR 每图输出 300 个查询、重复检测极多，故受影响最大。

**修复**：逐位复刻索引顺序（去掉两处 `np.sort`），CBPD_ODD 验证 mine=92 = ultralytics=92。

### 5.4 问题三：插值语义 vs 严格阈值统计

**现象**：匹配修复后，我的严格统计值（8-calves thr=0.25: P=0.899/R=0.916）仍低于 Ultralytics 报告值（P=0.942/R=0.961）。

**根源**：`ap_per_class` 把 P/R 阶梯曲线用 `np.interp` 插值到 1000 个 conf 网格点，`results.csv` 与 `model.val()` 报告的是**插值网格上的值**——线性插值穿过阶梯，在任意固定阈值处**系统性高估**（thr=0.25 处 R 高估约 4.5 个点）。这是 Ultralytics 的标准报告语义而非 bug，但"conf=x 下的 P/R"必须是严格阈值统计，两者不可混用（之前入文的第一版 P/R/F1 表正是混用了两种语义）。

### 5.5 修复与重跑

两个评测脚本（`evaluate_yolo_pr.py`、`evaluate_mmdet_pr.py`）同步修复并显式固定后处理参数（NMS IoU 0.7 / max_det 300 / conf 收集 0.001 / rect=False，MMDet 侧从 effective_config 读 test_cfg 逐项写入 JSON），重跑全部 56 个评测（~1 小时，A100 串行）。交叉验证：argmax-F1 值与训练记录吻合（如 RT-DETR XGain 0.9907/0.9913 vs 记录 0.9904/0.9913）。

## 六、最终协议与数据

### 6.1 协议（已写入文章 4.3.1 及每份 metrics.json）

- **主结果**：conf=0.25、IoU≥0.5 一对一匹配（同一 GT 的重复检测保留分数最高者，与 Ultralytics 评估器同语义）；F1=2PR/(P+R)；
- **补充结果**：验证集上各自最佳 F1 阈值下的 P/R/F1；
- **mAP**：评估器在置信度扫描下计算，不对应单一固定置信度；
- **后处理固定记录**：Ultralytics（NMS IoU 0.7、max_det 300、conf 收集 0.001、rect=False、640×640 letterbox）；MMDet（官方 1x test_cfg：score 阈值 0.05、NMS IoU 0.5、max_per_img 100）。

### 6.2 宏平均（14 数据集等权）

| 模型 | P@0.25 | R@0.25 | F1@0.25 | 最佳 F1 阈值 P/R/F1 | mAP50-95 |
|---|--:|--:|--:|---|--:|
| YOLO11m | 0.870 | 0.917 | 0.893 | 0.924 / 0.894 / 0.908 | 0.739 |
| RT-DETR-L | 0.719 | 0.946 | 0.807 | 0.919 / 0.895 / 0.906 | 0.744 |
| Faster R-CNN | 0.825 | 0.930 | 0.869 | 0.938 / 0.887 / 0.911 | 0.702 |
| RetinaNet | 0.778 | 0.922 | 0.839 | 0.923 / 0.870 / 0.894 | 0.700 |

逐数据集的完整三张主表与 argmax-F1 补充表见文章 4.3.1。

### 6.3 结论

1. **固定阈值结果依赖模型分数校准**：RT-DETR-L 的分类分数分布平坦，conf=0.25 处误检较多（Precision 宏平均 0.719），而其最佳 F1 阈值下 Precision 与其他架构相当；mAP 不受单一阈值影响。因此固定阈值 P/R/F1 与 mAP 必须共同解读，不能以单一工作点的 Precision 排名替代扫描指标（已写入文章表注）。
2. **Ultralytics 评测的两个隐性行为**（predict 默认 rect=True、match_predictions 的分数优先绑定）容易被自写评测脚本踩坑，已在服务器 README 中记录警告。
3. **`results.csv` 的 P/R 是插值语义**，与严格阈值统计不可直接比较；做固定阈值报告时必须用重推理的严格统计。

### 6.4 基于4.3已有数据的进一步结论（09-07复算）

以下结论由文章4.3节四架构、14个数据集的现有表格复算得到，不需要增加新实验，但均属于当前协议下的描述性发现。由于 Ultralytics 与 MMDetection 在输入尺寸、AMP、batch、运行环境和后处理配置上仍不完全一致，且尚未补充多随机种子和不确定性统计，这些结果不能解释为普遍的架构优劣或因果关系。

1. **不同模型对数据集相对难度的判断高度一致，数据集间差异明显大于模型宏平均差异。** 四种检测器在14个数据集上的 mAP50-95 排序高度一致，两两 Spearman 相关系数为 0.974~0.991。各数据集四模型均值从 Google Open Images 的 0.4464 到 CBPD_ODD 的 0.9413，跨度为 0.4949；四种检测器的宏平均仅从 RetinaNet 的 0.7001 到 RT-DETR-L 的 0.7437，跨度为 0.0435。由此可见，当前结果中跨数据集的性能变化远大于模型总体均值差异，说明四种架构共同识别出了较稳定的数据集难度次序。但这些差异可能同时关联场景、目标尺度、遮挡、标注几何、数据质量和验证集组成，不能归因于单一因素，也不能据此评价数据集质量。

2. **RT-DETR-L 与 YOLO11m 更接近并列领先，而不是存在明确的第一、第二名。** RT-DETR-L 在9/14个数据集上取得更高的 mAP50-95，YOLO11m 在其余5个数据集上更高；但二者宏平均仅相差 0.0047，逐数据集绝对差值平均为 0.0127，且12/14个数据集的差距不超过 0.02。因此现阶段只能表述为 RT-DETR-L 在当前协议下略占优势、YOLO11m 与其总体接近，不能在缺少多随机种子和置信区间的情况下断言差异稳定或具有统计显著性。

3. **不同数据集呈现出不同类型的检测困难，可以区分粗粒度检出与严格定位问题。** 按四模型均值计算，8-calves 的 mAP50 为 0.9358、mAP50-95 为 0.5497，差值 0.3861；MooTrack360 分别为 0.9218 和 0.6081，差值 0.3137；COLO 分别为 0.9340 和 0.6254，差值 0.3085。这三项在 IoU=0.5 时检出表现较高，但在严格 IoU 阈值下明显下降，说明其主要区分度体现在精确定位阶段。COCO cow subset 和 Google Open Images 的 mAP50 均值仅为 0.7642 和 0.7358，mAP50-95 均值为 0.5032 和 0.4464，表明其困难不只存在于高 IoU 定位阶段，在较宽松条件下也存在检测性能下降。现有汇总值只能定位问题出现的指标层面，具体原因仍需结合目标尺度、遮挡、误检漏检和标注一致性开展误差分析。

4. **统一固定置信度不适合单独用于不同架构的工作性能排名。** 从 conf=0.25 固定工作点切换到各“检测器—数据集”组合的最佳 F1 工作点后，YOLO11m、RT-DETR-L、Faster R-CNN 和 RetinaNet 的 F1 宏平均分别提高 0.0152、0.0990、0.0424 和 0.0555；其中 RT-DETR-L 从 0.8069 提升至 0.9059，表现出最明显的阈值敏感性。阈值优化后，YOLO11m、RT-DETR-L 和 Faster R-CNN 的最佳 F1 宏平均为 0.9079、0.9059 和 0.9113，最大差距仅 0.0054。因此固定阈值 P/R/F1 应用于展示同一工作点下的误检—漏检权衡，而不能替代 mAP 或经过统一校准的部署比较。最佳阈值来自验证集本身，只能用于说明工作点敏感性，不能直接视为独立测试集上的部署性能。

5. **不同数据集对模型和实验配置的敏感程度明显不同。** 四模型 mAP50-95 的数据集内最大差距在 MooTrack360、animals_10、CImage、COCO cow subset 和 NWAFU Cattle Dataset 上分别达到 0.1339、0.0838、0.0793、0.0752 和 0.0708，而 Dairy Cow、Google Open Images、CBPD_ODD 和 Cows2021 上仅为 0.0203~0.0230。前一组数据集更适合优先开展逐图误差分析和统一协议复核；后一组则呈现较强的跨模型共同高分或共同低分现象。由于四种模型当前未完全统一训练与评估配置，这里应称为“模型—协议敏感性”，不能将差距完全归因于架构本身。
