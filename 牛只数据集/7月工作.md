## 九、数据质量检查与训练决策

### 9.1 CVBD-5

服务器数据共 5,322 张图片和 5,322 个标签文件，其中：

- 有框标签：3,199
- 空标签：2,123
- 类别与坐标格式正常

抽查发现，CVBD-5 的问题不是只有少量空标签，而是现有标注整体质量较差：很多图片中的可见牛只没有被框出，部分图片也存在只标注部分牛只的情况。此前定位的 23 张连续帧异常图片只是较容易确认的漏标样例，不代表全部漏标范围，也不能通过只补这 23 张图片解决。

因此，现有标签暂不适合训练。进一步使用合并牛只检测模型对全部 5,322 张图片生成个体级预标注后，效果仍不理想，需要人工逐图大量补框、删错框和调整框。该数据集整体场景偏暗，牛只密集且遮挡严重，部分目标只露出局部身体，本身属于较困难的检测场景，当前模型预标注无法显著降低人工审核成本。

综合原标签质量、预标注效果和人工成本，当前决定暂不对 CVBD-5 开展全量重新标注，也不纳入现阶段训练。若后续确实需要补充暗光、密集遮挡场景，可利用连续帧高度相似的特点，每组只选择一张质量较好的代表图，删除过暗、模糊或无法可靠判断的图片，再对精选子集进行完整人工标注。否则应等待基础模型能力提升后重新生成预标注，再评估是否继续整理该数据集。

### 9.2 CMBN

CMBN 是相关论文将 `NWAFU Cattle Dataset` 与 `Dairy Cow` 整合后形成的数据集。两套源数据均已有标注，并且已分别完成单数据集训练，因此 CMBN 应视为已有标注的数据整合版本，而不是标签待补或待审查的新数据集。

## 十、CID-NOYT 数据整理与 YOLO11m 补充自测（AutoDL）

> 本节实验于 2026-07-14 在 AutoDL 服务器上完成。虽然使用的也是 CID 非 YouTube 子集，但服务器环境、数据划分方式和项目目录均与第五节不同，因此作为独立补充实验记录，不与 lab 服务器上的 CID 结果直接混用。

### 10.1 数据来源与划分

- 图片仅使用：`/root/autodl-tmp/cowCV_images/CID Dataset/images/`。
- 标注使用：`/root/autodl-tmp/cowCV_labels/CID-dataset/`。
- 明确排除 `CID Dataset/yt_images/`，因此命名为 **CID-NOYT**。
- 共 2056 张图片、2056 个同名 YOLO 标签，合计 3368 个 cow 框；额外的 `classes.txt` 不参与划分。
- 数据通过软链接组织到 `/root/data/cow-detection/full/CID-NOYT/`，不复制或修改源文件。
- 按牛 ID（文件名最后一个 `_序号` 之前的部分）分组，用固定 seed=42 做约 8:2 划分，保证同一头牛的 4 张图片不会同时出现在训练集和测试集。

| 划分 | 牛 ID 数 | 图片数 | 标注框数 | 比例 |
|------|----------|--------|----------|------|
| train | 411 | 1644 | 2695 | 79.96% |
| test/val | 103 | 412 | 673 | 20.04% |
| 合计 | 514 | 2056 | 3368 | 100% |

YOLO 数据配置：`/root/RUN-CODE/COWBenchmark/configs/datasets/available/CID-NOYT.yaml`。

### 10.2 训练环境与参数

| 项 | 值 |
|----|----|
| 服务器 | AutoDL（RTX 5090 32GB） |
| Python | 3.12.3 |
| PyTorch | 2.7.0+cu128 |
| ultralytics | 8.4.60 |
| 模型 | `yolo11m.pt` |
| epochs | 100 |
| imgsz | 640 |
| batch | 32 |
| workers | 8 |
| AMP | False（FP32） |
| 优化器 | auto，实际选择 AdamW（初始 lr=0.002） |

首次设置 `batch=128` 时发生 CUDA OOM，Ultralytics 自动尝试降到 64 和 32，但同一进程连续 OOM 后最终报 `CUBLAS_STATUS_ALLOC_FAILED`。重新启动进程并直接使用 `batch=32` 后训练完成；峰值显存约 30.6GB。日志中反复出现的 `OMP_NUM_THREADS="0"` 只是不合法的 OpenMP 线程数警告，可通过在导入 ultralytics 前设置 `os.environ["OMP_NUM_THREADS"] = "1"` 消除，不是训练失败的根因。

### 10.3 训练结果

100 epoch 总耗时 1562 秒，约 **26 分钟**。以验证集 `mAP50-95` 选择最佳模型：

| 结果 | epoch | mAP50 | mAP50-95 | precision | recall |
|------|-------|-------|----------|-----------|--------|
| **best** | **73** | **0.9851** | **0.8760** | 0.9545 | 0.9406 |
| last | 100 | 0.9752 | 0.8668 | **0.9574** | 0.9317 |

最佳轮到最后一轮的 mAP50-95 仅下降 `0.0092`，未达到本文采用的 `>0.02` 明显过拟合阈值。训练集 loss 到第 100 轮继续下降（box=0.3335、cls=0.1858、dfl=0.8270），验证指标后期小幅波动，整体训练正常。

训练产物位于：

```text
/root/RUN-CODE/COWBenchmark/outputs/runs/CID-NOYT/
├── weights/best.pt
├── weights/last.pt
├── results.csv
├── results.png
├── confusion_matrix.png
└── BoxPR_curve.png 等评估图
```

### 10.4 实验结论

1. CID 的非 YouTube 图片子集场景较统一，YOLO11m 自测表现较高（mAP50=0.9851，mAP50-95=0.8760）。
2. 按牛 ID 分组划分避免了同一头牛多视角图片跨 train/test 泄漏，比逐图片随机划分更可信。
3. YOLO11m 在 640 分辨率、FP32、batch=32 时已使用约 30.6GB 显存，RTX 5090 32GB 基本到达上限；后续训练不应再提高 batch。
4. 该结果属于同数据集自测基线，不能直接代表对 `yt_images` 或其他牛只数据集的跨域泛化能力。
