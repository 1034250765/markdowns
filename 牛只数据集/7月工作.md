# 7月工作

## 一、工作概述

7 月主要完成牛只目标检测数据集整理、标签核验、YOLO 格式转换、单数据集基线训练和独立测试集评估。截至 2026-07-16，已获得 13 个有效的 YOLO11m 单数据集训练结果；其中 `COCO`、`NWAFU_CD`、`CImage` 已修正 `Cow/cow` 重复类别并重新训练，新增 `8-calves`、`COLO`、`MooTrack360` 和 `XGain` 四个数据集。

本月还完成了 CID、Cows2021 Database 和 Dairy Cow 的数据准备与训练，排查了 CVBD-5 漏标问题，并根据数据规模、标签质量和跨域差异确定了暂不训练的数据集。

### 2.3 标签来源

- 原始图片：`/data1/yxli/CowsDatabases/<数据集>/`
- 人工复核真实标签：`/data1/yxli/new_labels/<数据集>/`
- 后续上传标签：`/data1/yxli/CowsDatabases_labels/<数据集>/`

训练前需确认具体数据集使用哪一套标签，不能用预标注覆盖人工复核标签。

### 2.4 统一训练参数

后续训练统一使用：

```text
model=yolo11m.pt
epochs=100
batch=32
imgsz=640
device=0
amp=True
```

首批 6 个数据集在 2026-07-11 训练时使用 `batch=16`；之后 CID、Cows2021、Dairy Cow 以及三个单类别重训实验使用 `batch=32`。

最佳模型以验证集 `metrics/mAP50-95(B)` 选择，同时记录 Precision、Recall 和 mAP50。Cows2021 与 Dairy Cow 还使用独立 test 集评估 `best.pt`。

### 2.5 环境问题记录

1. CentOS 7 的 glibc 2.17 较旧，直接创建的新 Python 环境可能缺少 `GLIBC_2.25+`。通过克隆兼容环境解决。
2. 默认 PyPI 下载较慢，切换清华镜像后恢复正常。
3. GitHub Releases 直连下载模型失败时，使用镜像下载到 `models/`。
4. RT-DETR-L 使用 `amp=True` 时曾在 epoch 15 后出现 NaN；改用 FP32 后训练稳定。YOLO11m 使用 AMP 未出现该问题。
