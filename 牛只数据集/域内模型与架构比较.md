### 1.2 checkpoint 选择规则

**Ultralytics（YOLO11m、RT-DETR-L）**

- 框架自动保存 `best.pt` / `last.pt`：`best.pt` 按综合 fitness = 0.1×mAP50 + 0.9×mAP50-95 保存；
- 文章 4.3 表格口径：**"最佳轮次"取 `results.csv` 中验证集 mAP@0.5:0.95 的最高行**，该行的 mAP、P、R 为同一轮权重（已验证：fitness-best 轮与 mAP 最高轮可能不同，例如两者在部分 run 上不重合，文章 225 行已声明该区别）；
- 本笔记第 3 节的 P/R/F1 即取自该行（口径与表格 mAP 完全一致）；
- 已实证：`results.csv` 某行的 P/R 与独立 `model.val()` 重评几乎一致（yolo11s/8-calves 第 53 轮：P 0.9517/0.9520、R 0.9403/0.9412、mAP50-95 0.5534/0.5530），差异为推理数值噪声。

**MMDetection（Faster R-CNN、RetinaNet）**

- `CheckpointHook`：`interval=1`（每轮保存）、`max_keep_ckpts=3`、**`save_best='coco/bbox_mAP'`（rule=greater）**；
- 产出 `best_coco_bbox_mAP_epoch_{XX}.pth`，XX 即该 run 中 `coco/bbox_mAP`（= mAP50-95 平均）最高的轮次；
- 每轮验证（`val_interval=1`），最佳轮与保存的 .pth 严格对应（已用 28 份评测的 scalars 对照核验，14/14×2 与文章表格 mAP 一致）。

### 1.3 输入尺寸

- Ultralytics：`imgsz=640`，letterbox 到 640×640（`rect=False`）；
- MMDetection：`Resize(scale=(1333, 800), keep_ratio=True)`，保持宽高比的长边 1333 / 短边 800，训练与测试 pipeline 一致；
- 两框架输入面积相差约 4 倍，这是架构比较中最主要的不可比因素之一（文章 209/223/330 行均已提示）。

### 1.4 训练预算与 batch 细节

- **YOLO11m**：全部 14 个 run 均 100 epochs。`animals_10`、`CBPD_ODD`、`HCRD`（首批，2026-07-11）batch=16；其余 11 个（含 COCO/NWAFU/CImage 单类修正重训、8-calves/COLO/MooTrack360/XGain 新增、Cows2021/diarycow/CID/Google）batch=32。
  - 注意 Ultralytics 的 `nbs=64`：优化器按名义 batch 64 归一，batch=16 时内部梯度累积 4 次、batch=32 时累积 2 次，**有效优化 batch 恒为 64**——这是 batch 16→32 对结果影响有限的机制原因。
- **RT-DETR-L**：全部 14 个 run 均 batch=12、`nbs=64` → accumulate=5，有效优化 batch 60。Cows2021 为从中断的 `last.pt` 断点续训完成（args.yaml 的 model 字段可证）。
- **Faster R-CNN**：目录 `100ep_bs16`。有效 batch 16 有两种实现：
  - 前 6 个（8-calves、animals_10、CBPD_ODD、CID、CImage、COCO，2026-07-25 单独启动）：micro-batch 16、无梯度累积；
  - 后 8 个（COLO、Cows2021、diarycow、Google Open Image、HCRD、MooTrack360、NWAFU_CD、XGain，由 `run_faster_rcnn_all.sh` 批量跑）：micro-batch 2 × 梯度累积 8（显存受限的等价实现）；
  - 两种实现的 lr 均为 SGD 0.02（官方 1x 基准 lr 对应 batch 16，`auto_scale_lr` 禁用、手动线性缩放，两种实现下数值相同）。
- **RetinaNet**：目录 `100ep_ebs16`（ebs=effective batch size）。全部 14 个由 `run_retinanet_all.sh` 以 micro-batch 2 × 累积 8 训练，lr=0.01（RetinaNet 官方基准）。
- 更新步数提示：各架构每 epoch 的优化器更新步数不同（有效 batch 64/60/16/16），若文章按第 665 行要求"报告实际更新步数"，需按各数据集训练图数量分别计算。

### 1.6 优化器实际选择（重要：均非配置显式指定）

- YOLO11m / RT-DETR-L 传 `optimizer=auto`，日志明确打印"ignoring lr0=0.01 and momentum=0.937 and determining best optimizer automatically"：

## 3. Precision / Recall / F1（2026-09-06 起为统一固定阈值 conf=0.25 协议）

### 3.0 排查记录（2026-09-06，重要技术档案）

初版 P/R/F1 数据（results.csv 行值 + 初版 MMDet 脚本）存在三个叠加问题，经逐层排查（图片→GT→像素→张量→预测→匹配→曲线→聚合）全部定位并修复：

1. **predict 默认 `rect=True`**（Ultralytics 8.4.92 的 predictor 行为）：predict 自动矩形输入（如 480×640）与训练验证的 640×640 letterbox 边界条件不同，密集俯拍场景中贴边目标的置信度系统性崩溃（8-calves 问题图 GT3：IoU=0.897 但 score=0.002）。修复：评测脚本显式 `rect=False`。
2. **匹配顺序语义**（最隐蔽）：Ultralytics `match_predictions`（8.4.92，非 scipy 路径）在 unique-pred / unique-gt 两步去重时**不重排索引**，隐含"同一 GT 的多个重复检测保留分数最高的预测"（预测按分数排序 → pred 索引升序 = 分数降序）。按"IoU 降序"实现的匹配会让高 IoU 但低分的重复框抢走 GT 绑定 → 固定阈值下大量 TP 丢失（RT-DETR 最严重：CBPD_ODD 92 个 GT 丢 10 个；因其每图 300 个查询存在大量重复）。修复：逐位复刻索引顺序，验证 92=92。
3. **interp vs 严格统计**：`results.csv` 的 P/R 是 1000 点插值网格上的报告值（`ap_per_class` 的 `np.interp` 曲线在 argmax-F1 网格点的值），在任何固定阈值处**系统性高估**（8-calves thr=0.25 处 R 高估约 4.5 个点）。这不是 bug 而是语义差异——固定阈值主结果必须用严格阈值统计。

修复后与 Ultralytics 评估器完全同语义：预测集 200/200 逐图一致（dataloader 链 vs predict(rect=False)）、GT 逐框一致（1633=1633）、匹配 92=92、argmax-F1 值与训练记录交叉吻合（如 RT-DETR XGain 0.9907/0.9913 vs 记录 0.9904/0.9913）。

### 3.1 协议与口径（现行）

- **主结果**：统一置信度阈值 **conf=0.25**、IoU≥0.5 一对一匹配（同一 GT 的重复检测保留分数最高者）；F1 = 2PR/(P+R)；
- **补充结果**：验证集上各自 argmax-F1 阈值下的 P/R/F1；
- **mAP**：评估器在置信度扫描下计算，不对应单一固定置信度；
- **后处理固定并记录**：Ultralytics（NMS IoU 0.7、max_det 300、conf 收集下限 0.001、rect=False、640×640 letterbox）；MMDet（官方 1x `test_cfg`：score 阈值 0.05、NMS IoU 0.5、max_per_img 100，逐项写入每份 metrics.json 的 `protocol.postprocess`）；
- **数据来源**：四模型均由对应最优 checkpoint 在 val 上重推理计算——`scripts/evaluate_yolo_pr.py`（yolo/rtdetr，2026-09-06 修复版）与 `scripts/evaluate_mmdet_pr.py`（同日修复版）；56 份 metrics.json 在 `outputs/evaluations/<framework>/<run>_val/`；
- 全部 14 个数据集均为 val 划分（含 Cows2021、Dairy Cow，与表格 mAP 同源）；
- **注意**：固定阈值下 RT-DETR 的 Precision 显著偏低（宏平均 0.719）——其分数分布平坦，conf=0.25 处误检较多；mAP 不受影响。固定阈值结果依赖分数校准，不能替代扫描指标。
