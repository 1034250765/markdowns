# Vite

> 整理自 2026-09-09 与小0的对话。一句话版本：**Vite 是前端项目的「开发服务器 + 打包器」二合一工具**——开发时让你秒起服务、改代码立刻生效；上线前把项目打包成精简的静态文件。

## 一、Vite 是什么

前端构建工具（build tool），Vue 作者尤雨溪开发。名字来自法语 *vite*（快），读作 `/vit/`。

要理解它得先知道它解决的问题：你写的 `.vue`、`.tsx`、`.scss` 浏览器**根本不认识**，需要有人做「翻译 + 组装 + 瘦身」，这就是构建工具干的活。Vite 把这件事拆成了两条流水线。

## 二、两个核心作用

| | 开发时 `npm run dev` | 构建时 `npm run build` |
|---|---|---|
| 干什么 | 起本地开发服务器 | 打包产出 `dist/` 静态文件 |
| 底层机制 | 浏览器原生 ESM 按需编译 | Rollup 打包 |
| 速度 | 秒级启动，与项目大小无关 | 一次性，慢点无所谓 |
| 产出 | 只在内存里，不落盘 | 可部署的上线文件 |

### 1. 开发时——让你写得爽

- **秒级冷启动**：不像 Webpack 先把整个项目打成一个大 bundle 再启动，Vite 直接起服务器，浏览器请求到哪个模块才编译哪个
- **热更新（HMR）**：改一行代码，浏览器不刷新，只替换改动的模块，页面状态全保留
- **实时翻译**：`.vue` / `.tsx` / `.scss` 即时转成浏览器能跑的原生 ES Module

### 2. 构建时——让线上跑得快

把源码交给 Rollup 打包，产出精简的静态资源：

- **Tree-shaking**：没被用到的代码直接删掉
- **压缩**：文件体积变小
- **代码分割**：按路由拆块，首屏只加载需要的部分
- **依赖预打包**：把 node_modules 里几百个小文件合并成单文件

## 三、为什么快（对比 Webpack）

| | Webpack | Vite |
|---|---|---|
| 开发时启动 | 先全量打包整个应用，再启动服务器 | 不打包，按需编译，直接启动 |
| 冷启动时间 | 项目越大越慢 | 秒级，与项目规模无关 |
| 热更新 | 从改动模块出发重建依赖图 | 精确到单个模块，毫秒级 |
| 构建产物 | 自己的打包器 | Rollup（新版也在迁移到 Rolldown） |

核心差异一句话：**Webpack 是「先做好一桌菜再开饭」，Vite 是「点什么炒什么」**。

## 四、类比

- **开发时**像吃火锅现涮——你要哪盘菜（哪个模块），服务员立刻端哪盘，不用等整个厨房备完料
- **构建时**像预制菜出厂——统一装盒、抽真空、贴标签，追求体积最小、运输最快

## 五、生态现状

Vue 3、create-vite、Nuxt、SvelteKit、Astro 等主流脚手架基本都默认用 Vite，卖点就一个：**开发体验**。Webpack 时代项目一大，`npm run dev` 等半分钟是常态；Vite 项目再大也是秒开。

## 六、和我有什么关系

以后如果给牛只检测做前端相关的东西——比如标注预览界面、YOLO 检测结果的可视化展示面板（网页版 demo）——脚手架一键生成项目时，背后的开发服务器就是 Vite。写界面时秒级热更新，部署前 `npm run build` 出静态文件挂到服务器上即可。
