模型容量与数据量的权衡，本质上是在平衡三件事：**能否拟合任务、会不会过拟合、是否覆盖部署时会遇到的变化**。

设模型容量为 \(P\)，训练样本数为 \(N\)。可粗略理解为：

![image-20260806202728950](images/image-20260806202728950.png)

增大 \(P\)：模型能表达更复杂的目标、背景和定位关系，逼近误差下降；但数据不足时会记住训练域的纹理、天气或相机偏差。

增大 \(N\)：同一分布的样本更多，能支撑更大模型，降低过拟合。

增加数据**多样性**：不一定让 \(N\) 变大，却能让模型少依赖某一域的伪相关，对 OOD 往往更重要。

放到检测任务中看：

- 只有 `100k` 张晴天驾驶图像：模型在晴天 In-Domain mAP 可能很高，但夜间、雾天或不同相机上的 OOD mAP 差。
- 保持总量 `100k` 不变，改为四个域各 `25k`：每个单独域的数据更少，In-Domain mAP 可能下降；但模型见过更多天气、背景和成像条件，OOD mAP 可能上升。
- 四个域各 `100k`：总量变为 `400k`，通常 ID 与 OOD 都更有机会提升；此时若效果不再增长，模型容量或训练策略可能成为瓶颈。
